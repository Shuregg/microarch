# ЛР 1. Многопортовые FIFO с разной шириной данных портов

Задание первой лабораторной работы — вам необходимо спроектировать блок FIFO, обладающий следующими особенностями:

- Все порты AXI-Stream
- Один порт для записи шириной 64 бита
- Два порта для чтения шириной 32 бита
- Размер FIFO - параметризуемый
- Использование AXI-Stream предолагает, что FIFO будет FWFT (first word fall-through)
- При этом, важно использовать на портах для чтения поле tuser, которое должно указывать на порядок следования 32 бит как части 64 бит слова. Так как мы разбиваем 64 бита на пару 32-бит слов и направляем в порты, то одна из 32-бит половин оказывается самой "старой" по порядку следования бит. В таком случае мы отмечаем самую "старую" 32 бит порцию данных флагом user = 1. Обратите внимание на то, что AXI-Stream запрещает вам изменять содержимое сигналов после поднятия valid во время ожидания handshake, но на tuser это правило не будет распространяться. При этом гарантируется, что в каждый момент времени чтение будет всегда приоритетно либо выполняться из порта со "старой" половиной 64-бит слова (у которой user == 1), либо из обоих портов сразу, либо не выполняться вовсе.
- Плюсом при сдаче лабораторной будет являться факт того, что при больших глубинах FIFO, блок будет раскладываться в двухпортовую блочную память (dual port ram).

Данное FIFO имитриует достаточно часто используемый элемент микроархитектуры, при котором поступающие данные расщепляются на фрагменты и отправляются для параллельной обработки в исполнительные устройства. Более конкретным примером может служить буфер инструкций суперскалярного процессорного ядра, в котором:
- Из кэша инструкций поступает кэш-слово большой ширины (обычно 64, 128 или 256 бит), содержащее сразу множество инструкций
- Кэш-строка разбивается на отдельные инструкции, и каждая инструкция может отправиться на параллельное исполнение. При этом для процесорного ядра критически важен набор флагов, говорящий о том, в каком порядке исполняемые в данный момент инструкции шли в памяти программ, чтобы аналазировать и разрешать конфликты по данным и обеспечить in-order-retire для инструкций.
